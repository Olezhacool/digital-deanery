# Разбор референса: приложение МГСУ (@mgsuappbot)

Изучен **бандл мини-приложения** (10 файлов, ~1 МБ), скачанный в `research/miniapp/`.
Живой интерфейс и сетевые вызовы не снимались: адрес мини-аппа не зафиксирован,
поэтому внутрь с валидным `initData` не заходили.

---

## 1. Что это на самом деле

Не «бот с кнопками». Бот — только точка входа, дальше открывается полноценное
веб-приложение (PWA) на React внутри Telegram.

| Слой | Что используется |
|---|---|
| Сборка | Vite + rolldown, код-сплиттинг по страницам (`InboxPage-*.js` и др.) |
| Фронт | React 19, JSX, без SSR |
| PWA | `manifest.json`: standalone, portrait, `theme_color #EEF0F5`, иконки 192/512 |
| Telegram | `telegram-web-app.js`, тема и `initData` из SDK |
| Иконки | lucide-react (`createLucideIcon-*.js`, `chevron-left-*.js`) |
| Шрифты | переключаемые: системный стек / `Manrope Variable` / «круглый» |

Отдельно сделан **anti-flash темы**: до первого кадра из `localStorage`
(`mgsu_theme_boot`) читаются атрибуты и CSS-переменные, чтобы тёмная тема не
начиналась со вспышки белого. Тема: светлая/тёмная + акценты.

## 2. Авторизация

- Telegram `initData` передаётся **в query-параметре** почти на каждом GET:
  `/api/schedule/groups?initData=...`
- Есть отдельный флоу привязки браузера к аккаунту:
  `/api/web/link/new`, `/api/web/link/claim`, `/api/web/link/poll`, `/api/web/session`.
- Паролей нет вообще: личность даёт подпись Telegram.

## 4. Чего у МГСУ НЕТ — и это наша ниша

Поиск по всему бандлу (регистронезависимо):

| Слово | Вхождений |
|---|---|
| справк… | **0** |
| заявк… | **0** |
| пересдач… | **0** |
| ведомост… | **0** |
| отчислен… | **0** |
| академ… | **0** |
| деканат | 4 — и все как адрес кабинета: «Деканат — кабинет 356 КМК» |
| сесси… | 16 — экзамены и отметки, не документы |
| зачёт… | 14 — те же отметки |

«Входящие» — это `subtitle: Сообщения от администрации`, то есть односторонние
объявления с ответом, а не заявка с трекингом статуса.

**Вывод:** приложение МГСУ — про *жизнь студента* (расписание, новости, знакомства,
выпускной). Конкурсное задание — про *деканат* (заявки, справки, пересдачи, статусы).
Пересечение только два: расписание и сессия. Остальное у них не покрыто — значит
копировать нечего, и это хорошая новость.

## 5. Что стоит взять

1. **`initData` вместо паролей.** Снимает требование «пароли только хешем» целиком:
   паролей нет. Личность проверяется подписью на сервере.
2. **`student-mode` у владельца** (`/api/owner/student-mode`) — переключение роли.
   Ровно то, что решает нашу проблему «жюри не заведёт второй Telegram-аккаунт».
3. **Экспорт `.ics`** для расписания — дешёвый плюс к проработанности сценариев.
4. **Код-сплиттинг по страницам** + ленивые чанки: первый экран грузится быстро.
5. **Anti-flash темы** через `localStorage` до первого кадра.
6. **Тон пустых состояний:** «Пока пусто. Напиши первым — например, что задали
   к следующей паре».
7. **Плитки разделов** с иконкой, цветом и подписью-объяснением
   («Входящие — сообщения от администрации»).

## 6. Что не брать

1. **`initData` в query-строке.** Утекает в логи сервера, историю, `Referer`.
   Передавать заголовком (`Authorization: tma <initData>`).
2. **288 эндпоинтов и 111 админских.** За три недели это гарантированный провал;
   нам хватит 25–35.
3. **Соцфичи:** знакомства, случайный чат, розыгрыши, перки, оформление.
   Баллов не дают, а модерация и риски — реальные.
4. **Отзывы о преподавателях.** Конфликтный контент, нужна модерация, которой у нас нет.

## 7. Чего не хватает для полной картины

- Адрес мини-аппа (origin), чтобы снять реальные экраны и увидеть вёрстку.
- Сетевой дамп с валидным `initData` — покажет форматы ответов и реальные статусы.

Без этого разбор архитектуры достаточный, а визуал — нет.
