## 04.11.2026 — Этап 0. Инфраструктура и бриф

**Инструмент:** OpenCode (desktop), модель DeepSeek V4.1 Flash Free.
**Роль ассистента:** постановщик инфраструктуры, аналитик задания.

### 1. Создание «сферы» проекта

**Промпт пользователя (дословно):**
> нам нужно с тобой созать изначально сферу, где все это будет, а точнее, гит хаб, там нужно будет создать репозиторий у меня еще 2е подопечных

**Что сделал ассистент:**
- Проверил окружение: `git 2.52.0` есть, `gh` (GitHub CLI) отсутствует.
- Установил GitHub CLI через `winget install --id GitHub.cli`.
- Запустил `gh auth login --web`, выдал одноразовый код для привязки аккаунта.
- Создал публичный репозиторий `digital-deanery`, склонировал локально.
- Заложил фундамент: `README.md`, `docs/roadmap.md`, `.gitignore`, `.gitattributes`, `.editorconfig`, первый коммит и пуш.

**Проблемы и как решались:**
- `gh` не в PATH после установки → в каждом вызове оболочки PATH перечитывается из реестра.
- GitHub отдал `HTTP 500` на странице `/login/device` и `HTTP 502/500` на `POST /user/repos`. Проверил `githubstatus.com` — «All Systems Operational», то есть ошибки транзиентные. Повторный запрос прошёл, но вернул `422 name already exists` — репозиторий фактически создался с первого «неудачного» запроса. Вывод: при 5xx от GitHub нельзя слепо повторять создание, сначала проверять `gh repo view`.

## 07.11.2026 — Этап 1. Референс, дизайн-система и первый рабочий кабинет

**Инструмент:** OpenCode (desktop), модель DeepSeek V4.1 Flash Free.
**Роль ассистента:** аналитик чужого кода, дизайнер-систематизатор, разработчик.

### 1. Разбор референса

**Промпт пользователя (дословно):**
> про анализируй это дело, и сделай именно такго бота, а потом напиши какой то файл, который даст понимание claude, как сделать дизайн. запусти этот проект локально, чтоб я посмотрел

**Что сделал ассистент:**
- Распаковал `mgsu-bot_1.zip`, прочитал `README.md`, `docs/DESIGN_PROMPT.md`, `bot/*.py` и `webapp/index.html` целиком.
- Понял архитектуру: aiogram-бот + aiohttp-сервер + один HTML без сборки + SQLite.
- Запустил веб-часть локально без Telegram-бота: `dev_server.py` (только aiohttp), `DEV_MODE=1`, фиктивный токен. Бот-поллер не поднимаем — он бы упал на неверном токене.
- Ошибка: порт 8080 был занят прошлым процессом → `OSError 10048`. Решение: остановить процесс через `Get-CimInstance Win32_Process`, перезапустить.

### 2. Дизайн-система для агентов

- Извлёк из референса токены, типографику, радиусы, компоненты и тон.
- Переписал под наш продукт: `docs/design-for-claude.md`. Это самодостаточный промт: агент по нему соберёт интерфейс без доступа к референсу.
- Добавил то, чего в референсе не было: статусы заявок, строки оценок, чат ассистента, скелетоны, пустые состояния.

### 3. Решение по стеку (изменение)

Было: Next.js + Prisma + Auth.js. Стало: **Python + aiohttp + SQLite + один HTML**.

Причина: референс заказчика построен ровно так, схема проверена, сборки нет, запуск одной командой, деплой простой. Для конкурсного MVP это меньше рисков, чем Next.js. Изменение зафиксировано в `AGENTS.md`, как требует правило.

### 4. Сборка кабинета

Сделано за один проход:
- `server/auth.py` — PBKDF2-SHA256 (150k итераций), HMAC-подпись cookie.
- `server/db.py` — схема: пользователи, пары, дисциплины, оценки, экзамены, задания, заявки, объявления.
- `server/api.py` — вход/выход, bootstrap, расписание по неделям, заявки, задания, ассистент, настройки.
- `server/ai.py` — ассистент по правилам: отвечает по расписанию, дедлайнам, оценкам и заявкам студента. Без внешней LLM и без ключей.
- `server/seed.py` — два студента с разными данными, расписание двух групп, оценки, долги, заявки.
- `webapp/index.html` — вход, главная, расписание, успеваемость, заявки, профиль, чат ассистента, тёмная тема, скелетоны.

### 5. Проверка

- Вход под `anna` → главная с ближайшей парой, дедлайнами и объявлениями.
- Вход под `maxim` → другие группа, средний балл (3.5), долг по английскому, другая заявка.
- Создание заявки → появляется со статусом «Новая» и номером `Д-0004`.
- Изоляция: `GET /api/requests/3` под Анной → **404**, `GET /api/requests/1` → 200.
- Ассистент: «Что сдать на этой неделе?» → список дедлайнов из данных студента.
- Все пять экранов рендерятся без ошибок в консоли.

**Ошибки по ходу:**
- Перепутал сигнатуру инструмента (`value` вместо `text` при заполнении поля) — исправлено после сообщения об ошибке.
- Сессия в cookie пережила сброс базы: приложение открылось под прошлым пользователем. Это не баг, но при демонстрации важно помнить.

**Скриншоты:** главная и вход — в панели Review.
