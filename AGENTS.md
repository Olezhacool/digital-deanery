# AGENTS.md — правила для ИИ-агентов

Этот файл читают все ИИ-ассистенты и субагенты, работающие над проектом.
Читать целиком перед первой правкой кода.

## Что за проект

«Цифровой деканат будущего» — работающий прототип личного кабинета студента для конкурса.
Полное ТЗ и разбор критериев — в `docs/brief.md`. План — в `docs/roadmap.md`.
Разбор референса (приложение МГСУ) — в `docs/bot-reference.md`.
Журнал работы с ИИ — в `docs/ai-log.md` (заполнять обязательно).

## Архитектура

Продукт = **Telegram-бот + мини-приложение** (WebApp), как у референса МГСУ, но про деканат.

```
Telegram
 ├─ бот (grammY)          → только вход: /start → кнопка «Открыть кабинет»
 └─ мини-апп (Vite+React) → личный кабинет студента/сотрудника
        │
        └─ API (Hono)     → все данные, проверка initData на сервере
             └─ SQLite (node:sqlite) → server/data/deanery.db
```

Бот ничего не хранит и не показывает — он просто отдаёт ссылку на мини-апп.
Вся логика и данные — в API. Паролей нет: личность даёт подпись `initData` Telegram.

## Стек (не менять без записи в ai-log и причины)

| Слой | Технология |
|---|---|
| Рантайм | Node.js 24 + TypeScript (strict) |
| Бот | grammY, long polling (работает без HTTPS и домена) |
| API | Hono + @hono/node-server |
| БД | SQLite через встроенный `node:sqlite` (без нативных модулей) |

| Авторизация | `initData` Telegram, HMAC-SHA256 проверяется на сервере (`server/src/auth.ts`) |
| Деплой | решается (см. roadmap): long polling на VPS в РФ — предпочтительно |

## Жёсткие правила (из ТЗ — нарушение = потеря баллов)

1. **Только вымышленные данные.** Никаких реальных ФИО, оценок, зачёток, телефонов, почт.
2. **Чужое не открывается.** Владелец данных определяется **на сервере** по `tg_id` из
   подписи `initData`. Никакой клиентской фильтрации «спрятать кнопку» — только сервер.
3. **Личность — только из подписи.** `initData` проверяется HMAC-SHA256 (`auth.ts`),
   при этом **не передавать его в query-строке** (утекает в логи) — только заголовком
   `x-init-data`. `BOT_TOKEN` только в `.env`, никогда в git и в клиентском бандле.
4. **Секреты только в `.env`.** Ключи API не попадают в клиент и в репозиторий.
5. **Мобильная версия от 360 px.** Мини-апп — мобильный по умолчанию, проверять на 360.
6. **Дисклеймер.** В футере и при входе: «Концепт для конкурса, не официальный сервис вуза».
7. **Без логотипа вуза.** Только собственный знак.
8. **Лицензии.** Шрифты и иконки — OFL/MIT/Apache. Не тащить картинки без лицензии.

## Правила кода

- TypeScript strict, без `any` без причины.
- Валидация входных данных — на сервере (сейчас минимальная, расширять).
- Никаких `fetch` к внешним API из клиента, если там секрет.
- Компоненты мини-аппа — в `web/src`, имя файла = имя компонента в PascalCase.
- Тексты интерфейса — по-русски, без канцелярита.
- Пустые состояния и состояния загрузки — обязательны для каждого экрана.

## Как работать

1. Сначала прочитать `docs/brief.md` и этот файл.
2. Перед крупной фичей — короткая спека в `docs/`, потом код.
3. Проверять результат: `npm run typecheck` (server), `npm run build` (web).
4. Ошибки ИИ не скрывать — записывать в `docs/ai-log.md` вместе с исправлением.
5. Не удалять чужие файлы и не переписывать чужой код без необходимости.
