# Цифровой деканат будущего

Личный кабинет студента как **Telegram-бот + мини-приложение**: расписание, оценки,
справки и заявки — в одном месте, без очереди в деканат.

> Статус: **бета-каркас**. Бот и мини-апп работают локально; наполнение экранов — в процессе.

---

## Что это

Бот — только входная точка: `/start` отдаёт кнопку, которая открывает мини-приложение.
Само приложение — личный кабинет студента и панель сотрудника деканата.

Паролей нет: личность даёт подпись `initData` Telegram, проверяемая на сервере.

## Архитектура

```
Telegram
 ├─ бот (grammY)          → /start → кнопка «Открыть кабинет»
 └─ мини-апп (Vite+React) → кабинет студента / сотрудника
        └─ API (Hono)     → все данные, initData проверяется на сервере
             └─ SQLite (node:sqlite) → server/data/deanery.db
```

Подробный разбор референса (приложение МГСУ) и что мы у него берём/не берём —
в [docs/bot-reference.md](docs/bot-reference.md).

## Стек

| Слой | Технология |
|---|---|
| Бот | grammY (long polling) |
| API | Hono + @hono/node-server |
| БД | SQLite (встроенный `node:sqlite`) |
| Фронт | Vite + React 18 + TypeScript, CSS-токены |
| Авторизация | initData Telegram (HMAC-SHA256 на сервере) |

## Запуск локально

```bash
# 1. Сервер (бот + API)
cd server
copy .env.example .env     # вписать BOT_TOKEN от @BotFather
npm install
npm run dev

# 2. Мини-апп (в отдельном терминале)
cd web
npm install
npm run dev
```

Открой бота в Telegram → `/start` → «Открыть кабинет». API слушает `http://localhost:3000`,
мини-апп — `http://localhost:5173` (значение `WEBAPP_URL` в `.env`).

> Для отладки API без Telegram: `DEV=true` в `.env` и добавь `?tg=123&name=Тест` к запросу.

## Роли

| Роль | Что умеет |
|---|---|
| **Студент** | профиль, расписание, оценки, заказ справок, статусы заявок |
| **Сотрудник / Владелец** | видит все заявки, меняет статусы (`ADMIN_TG_IDS` в `.env`) |
